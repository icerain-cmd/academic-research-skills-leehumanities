# 인용 감사

## 세 가지 질문을 분리하라

1. **서지 실재:** 이 저작·판본·기사가 실제로 존재하는가?
2. **열람과 위치:** 무엇을 직접 읽었으며 해당 구절을 다시 찾을 수 있는가?
3. **주장 지지:** 그 구절이 현재 원고의 주장을 어느 범위에서 지지하는가?

DOI 확인, 도서관 목록 일치, 파일 해시 일치는 첫 번째 또는 두 번째 질문의 일부다. 세 번째 질문은 실제 구절과 문맥을 대조해야 한다. 인용문을 정확하게 옮겼더라도 저자의 뜻을 뒤집거나 다른 범위의 주장에 쓰면 지지가 성립하지 않는다.

## 주장별로 검토하라

먼저 핵심 논증, 직접 인용, 역사적 사실, 특정 저자의 견해, 수치·최초 주장부터 확인하라. 서지의 저자·제목·연도·판본과 본문-참고문헌 대응을 점검한 뒤 원문 구절을 읽어라. 앞뒤 문맥, 부정·가정·가능성 표현, 논쟁 상대의 말을 저자 자신의 주장으로 오인했는지 확인하라.

근거가 부분적이면 문장 범위를 좁히거나 서로 다른 주장을 나누어라. 출처에 없는 연결은 현재 원고의 해석으로 명시하고 필요한 논증을 제시하라. 확인할 수 없는 직접 인용·쪽수는 만들지 마라. 중요한 미확인 근거는 별도 검토 메모에 남기고 원고의 준비 상태에 반영하라.

## 근거 기록 형식

기계 검사를 사용할 때는 `leehumanities-evidence/1.0` 형식과 번들 스크립트가 실제로 요구하는 필드를 따르라. 스크립트의 `--help`와 제공 예제를 읽고, 필드명·허용값을 추정해 바꾸지 마라.

| 레코드 | 기록할 필드와 의미 |
|---|---|
| 출처 | `source_id`, `title`, 필요한 경우 `uri` 또는 `local_path`, 파일을 대조했으면 `sha256` |
| 실재 근거 | `existence: CONFIRMED` 또는 `UNRESOLVED`, 확인 근거를 설명하는 `existence_basis` |
| 접근·열람 | `access_scope`, 실제 읽은 범위를 적는 `read_scope`, `accessed_at`, `read_by` |
| 주장 | `claim_id`, 원고의 해당 주장인 `text`, 그 주장의 `evidence` 목록 |
| 대조 상태 | `status: VERIFIED` 또는 `UNVERIFIED`; 대조 수행 여부와 검증 범위를 함께 기록 |
| 지지 판단 | `support: SUPPORTED`, `PARTIAL`, `UNSUPPORTED`, `UNASSESSED` 중 하나 |
| 위치·내용 | `verification_scope`, `locator`, 직접 대조한 짧은 `excerpt`, `assessor`, `assessment_note` |

`locator.kind`는 `page`, `section`, `paragraph`, `folio`, `line`, `timestamp` 중 해당 자료의 실제 위치 체계를 사용하라. `locator.value`에는 재확인할 수 있는 정확한 위치를 적어라. 쪽이 없는 문서에 쪽을 만들어 넣지 마라. 판본·PDF 쪽 구분은 별도 서지 메모에도 보존하라.

`VERIFIED`는 명시한 범위의 대조를 실제로 수행했다는 뜻이다. 지지 판단과 별개로 기록하라. 예를 들어 원문을 대조하여 주장을 지지하지 않는다고 확인했으면 `VERIFIED`와 `UNSUPPORTED`를 함께 기록할 수 있다. 출처를 열지 못했는데 메타데이터만 보고 본문 지지를 `SUPPORTED`로 표시하지 마라. `UNASSESSED`는 판단하지 않았다는 뜻이며 약한 긍정 판정이 아니다.

추가 출처의 검증 결과를 현재 주장에 자동 전이하지 마라. 같은 문헌이라도 주장마다 필요한 읽기 범위가 다르다. 재검토 후 기존 판단을 바꾸면 원고 버전과 변경 이유를 남겨라.

## 기계 검사와 학술 판단

`research_audit.py evidence-validate --input JSON --run-dir DIR`를 실행하고, 필요하면 `--corpus`로 해당 manifest를 넘겨라. 로컬 파일 검증에 명시적 `source_root`가 필요한 경우 현재 등록한 자료 루트를 사용하라.

검사 결과가 통과하면 **검사한 필드·연결·파일 조건이 통과했다**고 보고하라. 스크립트가 인용 내용의 참, 해석의 적절성, 독창성, 완전한 원문 열람을 입증했다고 말하지 마라. 사람이든 모델이든 작성한 `assessment_note`는 검토자의 판단이며 독립적인 인증서가 아니다.

## 원고에는 자연스러운 인용을 남겨라

감사 상태, 해시, 접근 실패 로그, 검증 등급을 논문 문장 안에 삽입하지 마라. 학술지 인용법과 저자의 문체에 맞는 각주·본문 인용·참고문헌을 사용하라. 미확인 주장을 검증 태그만 지운 채 확정 문장으로 남기지 마라. 근거가 없는 문장은 삭제·제한·재논증하고 그 처리 내역을 검토 메모에 기록하라.
